# Integrity probes

Use isolated fixtures, temporary repositories, or local test seams without changing user data. An execution witness records input, actual entry path, and observed results/effects. Establish expected outcomes independently.

## Parsers and identities

Run the parser version selected by production and pass its output through the real traversal/adapter. Assert the public result. Finding an expected node somewhere does not prove the consuming branch is reachable under its parent and guards.

When identity matters, test identical spellings with different lexical owners. Exercise relevant comments, whitespace, aliases, nesting, and alternate supported forms. Disclose unsupported forms; a text approximation cannot justify a compiler-backed claim.

If a probe misses a branch, question the probe, enclosing conditions, configuration, and grammar version. Establish a counterexample or grammar contradiction before declaring dead code. Capture representative real external inputs when possible; minimal grammar examples serve a distinct purpose.

## Primary and fallback paths

Exercise primary success, expected unavailability, meaningful failure, and consumer response. Use observable results/calls or a narrow test seam to distinguish paths. Check swallowed failures, partial state, and weakened guarantees. An intentional fallback is valid if it meets the contract or accurately reports limits; relabeling cannot fix a required missing capability.

## Parallel implementations

Locate ingresses and configuration variants before choosing a canonical owner. Compare contracts including errors, order, state, and compatibility. For paths intended to agree, run distinguishing inputs against both, including adverse cases. Differences can be intentional, and agreement on samples is not universal equivalence.

After migration, verify routing. Importing a replacement directly in a test does not establish that the command/worker/API stopped using the old implementation.

## Checks and metrics

Exercise a valid case so an always-failing checker cannot look correct, and an invalid case so an always-passing checker cannot look correct. When practical, remove the relevant operation and confirm the regression check fails. Do not require destructive production execution.

Recompute metric examples that distinguish plausible defects, such as double counting or missing coverage. A fixed sample count does not establish the whole calculation. Classify status by supporting evidence: constants can describe static support accurately, while computed values can overstate readiness. Follow errors, partial output, and stale inputs to consumers.
