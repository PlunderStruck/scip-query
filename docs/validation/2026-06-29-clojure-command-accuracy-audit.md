# Clojure Command Accuracy Audit

Date: 2026-06-29

Corpus: Logseq at `/Users/aydansalois/Documents/GitHub/logseq`, using the local `scip-query` build at `/Users/aydansalois/Documents/GitHub/scip-query/dist/cli.js`.

This audit checks whether scip-query's public command surface gives accurate Clojure and ClojureScript answers. Accuracy here means the reported files, namespaces, definitions, references, calls, dependency edges, and health findings correspond to facts visible in the indexed Clojure source. A command is strong when it gives precise and useful Clojure results, partial when it completes and returns useful evidence with known blind spots, weak when its output is empty or misleading for visible Clojure facts, project-level when it is not language-specific, and N/A when the command is intentionally for another language or framework.

## Corpus Facts

The Logseq index used for the audit contained:

- 3,303 indexed documents.
- 30,214 symbols.
- 463,436 references.
- 842 `.cljs` files reported by `files "*.cljs"`.
- Clojure capability matrix status: indexing partial because `scip-clojure` was not on `PATH`, source facts available, semantic provider unavailable, detectors available, cleanup verification available through `npx clj-kondo --lint .`.

Representative target: `frontend.db:transact!` in `src/main/frontend/db.cljs`, lines 42-54.

Update after the 2026-06-29 accuracy pass:

- `call-graph frontend.db:transact! --json` now reports 43 callers and 4 callees.
- `slice frontend.db:transact! --json` in backward mode now reports 23 connected symbols.
- `dataflow frontend.db:transact! --json` now reports 4 producers, 30 consumers, and 54 usage sites.
- `affected frontend.db:transact! --json` now reports 118 affected consumer symbols.
- `imported-by frontend.db.conn --json` now reports 24 namespace-labeled importer files.
- `health --scope src/main --json` still completes quickly, with score 73 in the Logseq smoke run.

Update after the remaining parity pass:

- Source facts now record Clojure `defprotocol`, `defrecord`, `deftype`, `extend-type`, and `extend-protocol` member forms.
- `members` and `methods` now return source-backed Clojure protocol/record/type method rows when SCIP child symbols do not model them.
- `wrapper-candidates`, `passthrough-candidates`, and `convergence` avoid treating Clojure macro definitions as ordinary wrapper/passthrough/consolidation evidence.
- `self-audit` now reports a Clojure source-fact oracle with `oracleKind: "source"`; this is useful regression evidence, not a TypeScript-style compiler oracle.

## Current Verdict

Clojure support is strong for source inventory, definitions, incoming references, qualified namespace call graph edges, backward/forward slice over those edges, impact analysis through reference consumers, namespace/file dependencies, namespace reverse import lookup, dependency cycles, hotspots, health runtime, and broad maintainability scans. It now has practical source-backed support for protocol/record member navigation, macro-safer cleanup evidence, and source-backed self-audit. It is still not on par with TypeScript's compiler semantic provider.

The most important practical distinction is this: scip-query can answer "where is this Clojure symbol defined?", "who references it?", "what qualified namespace calls does this function make?", "what source-visible protocol/record methods are declared?", "what transitive symbols are affected?", "which files/namespaces depend on this?", "are there cycles?", and "what broad health signals exist?" It still cannot prove full Clojure protocol dispatch or macro-expanded runtime semantics the way the TypeScript path can ask the compiler.

## Gaps To Close

1. Keep expanding Clojure callee evidence beyond namespace-qualified calls.
   Namespace-qualified calls now resolve through source imports, but protocol dispatch, record member calls, and macro-expanded calls still need separate evidence if they should reach TypeScript-like precision.

2. Keep refining macro-aware detector labeling.
   Macro definitions are now filtered out of wrapper/passthrough/convergence evidence. ClojureScript component macros such as `defc`/HSX may still need framework-specific labeling when macro-expanded component bodies look like ordinary functions.

3. Consider a stronger Clojure self-audit oracle.
   `self-audit` now has a Clojure source-fact oracle. A future clj-kondo/scip-clojure-backed oracle could raise confidence beyond lexical source evidence.

4. Improve protocol dispatch semantics beyond declaration navigation.
   `members` and `methods` now support source-visible protocol/record/type declarations. Resolving dynamic protocol dispatch remains a deeper semantic problem.

5. Preserve the current health runtime model.
   `health --scope src/main` completed quickly and without arbitrary Clojure bounds. Any deeper Clojure analysis should stay behind cached indexes or shared evidence so TypeScript and existing health performance do not regress.

## Recommended Next Implementation Order

1. Add a Clojure row to the language playbook that recommends the strong command families and warns about current partial ones.
2. Explore a clj-kondo/scip-clojure-backed self-audit oracle.
3. Add framework-aware labeling for ClojureScript UI macros if Logseq cleanup output still over-reports UI component scaffolding.
