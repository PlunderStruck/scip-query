## Required outcome

A call relationship connects the source invocation with its established declaration target. It must retain the correct owner and source position, and disclose when the executing implementation cannot be established. A missing supported relationship and an invented relationship both prevent reliable exploration. Runtime-selected implementations require additional evidence beyond a static declaration reference.

Use small valid TypeScript programs with independently expected calls and values. Where useful, execute the program to distinguish declarations from the implementation that actually runs. Exercise the public evidence command with a real compiler index, both graph directions, and explicit unresolved-call coverage. Record unsupported cases rather than declaring arbitrary runtime analysis complete.

## Existing flow

The public evidence handler calls graphEvidence and systemMapTopology. Incoming and outgoing call expansion share scipOccurrenceCallTargetsForRange in src/symbols/graph/scip-occurrence-call-targets.ts. That owner joins parsed invocation ranges to stored compiler occurrence ranges, rejecting ambiguous matches and targets with an observed source write. programExecutionFrontiers reports invocations left without established repository targets.

sourceCallTargetWasWritten uses the cached, per-parsed-file sourceBindingResolver in src/source/ast/source-binding-identity.ts. Before this pass, the resolver used TypeScript declaration identities for variable writes and followed constant identifier aliases for property writes, but retained only the root declaration and dropped the member path. Its alias walk accepted bare identifiers, so equivalent parenthesized and type-asserted expressions needed distinguishing tests.

## Comparable features and conventions

tests/queries/graph/incoming-call-evidence.test.ts and graph-source-identity.test.ts use IndexerHistoryFixture, the real bundled compiler, and the built public CLI with watching disabled. They assert exact canonical symbols and independent expected owners. Reuse that fixture and the established graph output rather than introduce another graph implementation. The existing static-value-flow and runtime consumers share sourceBindingResolver; changes must preserve their conservative handling of complete object values and ambiguous writes.

## Reuse and ownership decisions

Keep binding and property-write classification in the existing source binding owner. Preserve compiler occurrence identity and the shared incoming/outgoing resolver. If mutation matching needs richer member information, represent it within that owner and apply it consistently; do not attach a second name-based heuristic to the CLI. Exact static member paths may distinguish sibling properties; computed or ambiguous paths require conservative overlap handling.
