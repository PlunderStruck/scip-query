## Required outcome

An index is a saved collection of declarations and references emitted by a language indexer. A graph projection is the selected set of relationships the tool constructs around requested program entities. Correct index records are necessary but insufficient: the projection must also preserve identity, source ownership, relationship meaning, evidence strength, scope and omitted/unresolved work.

The user requests repeated investigation and repair until the audit matrix and all discovered defects are resolved. Do not stop after fixing only the two known cases. Do not claim that finite checks prove completeness for arbitrary programs or unsupported language/runtime mechanisms.

## Existing flow

The public `evidence` handler validates selectors, families, direction, depth and output bounds, then `graphEvidence` calls `systemMapTopology`. The topology builder combines stored compiler identities/references, source syntax facts, runtime-boundary observations and selected program analyses. Provider contracts in `src/domain/graph-relation-providers.ts` define each emitted subtype's meaning and permissible strengths. Projection selects families/directions and preserves folds/continuations and coverage.

The prior repair makes both call directions use `scipOccurrenceCallTargetsForRange`, which joins parsed invocation token ranges to compiler occurrence ranges. `callSiteOwner` retains the nearest callable's line and column coordinates. `lexicalCallOwners` resolves indexed declarations where possible. Source-only owners enter `SystemMapSourceConstruct`, which currently loses columns; `canonicalSourceConstruct` may then choose a different same-line callable. `programControlElementsForTopologyNodes` similarly sends only line ranges to `behaviorControlAnalysis`, whose `findCallableNode` can select another nested/sibling function.

The TypeScript index producer now declares UTF-16 coordinates (producer contract 3) and rejects caught compiler visitor failures. The installed VM build includes those earlier repairs. It does not yet include this audit's repairs. VM installation and two known reproductions are recorded in `2026-09-08-graph-followup-and-vm.md`.

### Compiler constructor coverage

The pinned FileIndexer visitor handles identifiers, string literals and constructor declarations but never visits the `super` keyword as a reference (`node_modules/@sourcegraph/scip-typescript/dist/src/FileIndexer.js:88-98`). Its ordinary `new` handling converts a referenced class to its constructor symbol. The compiler itself resolves explicit `super()` signatures: a real TypeScript 5.9.3 probe identified the base constructor, including an inherited constructor through a class with no explicit constructor. A conditional/computed base did not establish that declaration.

Implementation decision: extend the existing shared full/incremental document runtime with `typescript-super-calls.ts`. Use the compiler signature only after proving a direct class binding and its static ancestor chain; reuse the producer's declaration-based `scipSymbol` and occurrence serializer. Do not guess from base-class text or add a parallel query-only relationship. Teach the source invocation parser to recognize the `super` keyword so both graph directions consume the newly indexed occurrence through their ordinary shared resolver. Producer contract 4 / adapter 6 invalidate incompatible generations. This is being validated; the VM remains on producer 3 until a later installation.

## Remaining support boundaries

- SCIP references identify declared program entities. They do not execute code or supply a complete runtime object/dispatch model. General virtual dispatch, cross-file callable replacement, heap aliasing, reflection, generated dispatch and arbitrary interprocedural value/exception flow remain explicit limits.
- HTTP/queue/Effect/capability candidates require deployment, receiver, registry or instance evidence before an agent may call them executable handoffs. A source name or matching address alone cannot supply that proof.
- Language support is per provider. The real TypeScript compiler fixtures, JS/Rust/Python source cases and generic-literal negative cases do not establish equal support for every indexed language.
- Depth/budget omissions remain recoverable folds; unsupported edges remain disclosed frontiers. Neither `accounted` nor an empty result proves the absence of all possible runtime behavior.
- No finite fixture/property suite can establish that arbitrary future programs contain no unseen counterexample. This audit closes the enumerated supported-case defects; it does not claim a complete executable model of every program.
