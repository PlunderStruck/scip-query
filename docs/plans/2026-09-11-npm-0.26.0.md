# Prepare npm 0.26.0

## Scope and existing release path

Prepare a tested npm artifact from this repository. Publishing is a separate
operation: this task stops after the release dry run and installation smoke
checks, with the exact archives and verification record retained for review.

At preparation time the npm registry's latest main package is `0.24.0`; this
checkout is `0.25.0` with further changes since its release-notes commit
`7fb9064a`. Prepare `0.26.0` because the accumulated changes include removed
commands and JavaScript exports, changed human output, and revised agent
workflows. Keep the existing `0.24.1` and `0.25.0` changelog sections as history
of changes included in this release, without implying those versions were
published.

The existing release coordinator, `scripts/release-npm.ts` and
`scripts/npm-release.ts`, owns preflight, packing, registry comparison, and
release records for the main package and its Windows binary dependency.
Reuse it through `npm run release:npm:dry-run`, following
`docs/WINDOWS_SIDECAR_RELEASE.md`. Keep the sidecar at `0.13.1` if provenance
verification and comparison with the published archive establish identical
bytes. Do not introduce a second publishing path.

## Preparation checklist

- Update the main manifest, lockfile, and the release-version assertions in
  `runtime-support-contract.test.ts` and `windows-sidecar-doc.test.ts` to
  `0.26.0`; leave dependency versions
  unchanged. Document command/API migration, output, accuracy, and measured
  indexing performance in the changelog.
- Review and commit these release inputs on `main`. Preserve the unrelated
  untracked LaunchPoint validation document.
- Use a clean detached worktree at that commit for the release coordinator's
  complete tracked/untracked cleanliness requirement. Supply dependencies and
  verified ignored Windows binaries, then build before running preflight
  because tests consume generated artifacts.
- Run `npm run release:npm:dry-run`: type checks, production dependency audit,
  the complete test suite, formatting/lint, build, API contract and consumer
  checks, skill links, both package archives, and live registry comparison.
- Retain both archives outside the clean checkout and require their hashes to
  match the dry-run record. Check packed exports and skills, install the main
  archive into an isolated prefix, and smoke-test the installed CLI against a
  small source fixture.
- Retain the exact source revision, release-state record, package hashes, and
  validation logs with the artifacts. Report readiness and any unresolved
  limitations. Leave npm publication to a subsequent explicit instruction.

## Accuracy and performance limits

Do not claim complete TypeScript/runtime accuracy or a one-minute cold index.
The latest recorded LaunchPoint result is 167.4 seconds and 12.5 GiB peak
process-tree memory, with compiler documents and runtime observations equal
to the preceding build. See the committed runtime-indexing benchmark records
and `2026-09-11-cold-index-budget.md` for the remaining work.
