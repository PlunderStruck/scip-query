# Rust dead-code certification

Date: 2026-07-10
Status: Complete; hardening landed, certification remains insufficiently evidenced
Parent: [`Accuracy Hardening and Health Certification Roadmap`](../accuracy-hardening-goal.md)

## Goal

Assign an evidence-backed certification state to Rust `dead-code` findings without inheriting TypeScript assumptions. Done means a pinned three-repository corpus produces a deterministic reviewed sample, every invalid finding belongs to a named archetype with a regression, at least one known-positive case proves useful dead code remains visible, and the roadmap records whether Rust is certified, qualified, experimental, unsupported, or insufficiently evidenced.

Within this slice, a Rust repository-dead definition is a function, value, or member for which the index, source scan, tests, trait contracts, macro and derive expansion boundaries, ABI or registration attributes, Cargo target structure, feature configuration, and public library surface provide no evidence of a consumer. This is a conservative deletion claim. A definition whose runtime caller may be generated by a compiler, macro, trait object, framework, linker, or external crate is not repository-dead merely because a direct textual call is absent.

## Reuse Audit

- Extend the existing `health-dead` mode with a validated `--language` option and language-specific default corpus. Do not create a second Rust calibration script.
- Reuse `normalizeDeadCandidate`, `deterministicSample`, `summarizeCalibration`, `resample`, and `summarize`; their contracts already carry `language` and do not encode TypeScript truth.
- Reuse the existing detached-worktree and temporary-cache shell. It already protects dirty corpus checkouts and records immutable commits.
- Preserve `implicitUsageReason` in calibration rows. It is existing detector evidence needed to determine whether the current `dead-code` kind package-deals proven deadness with uncertain framework reachability.
- Reuse the Rust exclusion classifier and symbol parser when remediation is evidence-supported. Add a new policy unit only if the baseline proves that existing dispositions cannot express the required output distinction.
- Do not add Cargo/public-surface configuration or framework-name lists before the corpus demonstrates a false-positive class they would correct.

## Stress-Test Findings

- A large workspace may time out or fail indexing for environmental reasons. That yields `unsupported` or `degraded` evidence for that repository, never a clean zero.
- Cargo features and target-specific code can be unreachable in the default build but live in another supported configuration. The certificate must name its feature/target basis or remain conservative.
- Procedural macros and derives execute code generated outside the source graph. Unknown attribute macros are evidence of an external caller boundary, not automatically proof of either liveness or deadness.
- Trait implementation methods are contract units invoked through trait dispatch. Suppressing them can protect precision but must remain visible as excluded applicability so macro- or trait-heavy repositories do not look artificially clean.
- Public `pub` items in a library crate can have consumers outside the analyzed repository. The same token in a binary-only crate has no such external surface, so a global `pub` exemption would destroy recall.
- `cargo check` validates compilation after deletion but does not exercise runtime registration, dynamically loaded symbols, optional features, or external downstream crates. Checker success is corroboration, not the whole truth rule.
- The live corpus worktrees are dirty. Detached worktrees at pinned commits are mandatory and cleanup failures must be surfaced.

## Execution and Ship Order

1. Generalize the harness and prove TypeScript compatibility plus a SynthRunnerRust smoke.
2. Generate a full Rust frame and fixed-seed baseline before changing detector behavior.
3. Review all sampled rows and rank archetypes by count and causal mechanism.
4. Fix shared causes in descending impact, adding a known-positive regression in the same slice.
5. Replay the original rows and review a replacement sample.
6. Publish a certificate only if every statistical and recall gate passes; otherwise publish the exact failed criteria.
7. Run repository verification and commit the shared calibration records with the code/docs that produced them.

The one-way door is public interpretation: changing a Rust row from direct dead code to implicit or unsupported affects health counts and cleanup plans. Raw calibration packets and verdict overlays must be retained so the decision can be audited and renewed.
