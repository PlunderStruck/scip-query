# Persistent Incremental Index and Cache Lifecycle

## Outcome

Each checkout owns one logical SCIP index that survives process and agent-session boundaries. A source edit normally derives the next immutable generation by replacing only affected documents. A whole-project rebuild remains a conservative fallback for missing or incompatible state, unsupported changes, or failed incremental validation. Superseded internal generations and caches are reclaimed without risking a live checkout.

Runtime-boundary facts use the same incremental model. Direct observations and facts derived through calls, values, mounts, registrations, and protocol identities are reused only while all of their recorded inputs remain valid. A change recomputes the affected proof closure; it does not rescan the repository or preserve a stale answer.

## Worktree model

Each Git worktree owns one mutable local cache namespace and its own accepted immutable index generation. A repository-shared generation is a read-only checkpoint for one exact committed Git tree plus one exact indexing configuration. A clean worktree may publish or attach that checkpoint. A new dirty worktree may fork the checkpoint matching its committed `HEAD`, then apply only its private changes to its local generations. No worktree mutates another worktree's accepted generation or the shared checkpoint.

This is branching by immutable generation, not copying another worktree's current dirty cache. Git worktrees copy committed files but not uncommitted edits; the shared `HEAD` checkpoint is therefore the safe common base. Reflinks are used when the filesystem supports them and ordinary copies are the fallback. Worktree leases protect every live base/current generation. When `git worktree remove` makes a worktree disappear, the next safe repository lifecycle sweep removes its owned local cache; a now-unreferenced shared generation ages out after the grace period or earlier under the repository byte budget.

- Configured TypeScript project directories no longer enter the project fingerprint as unreadable files.
- Successful publication prunes obsolete TypeScript fragment generations.
- Local SQLite retention is current plus one recovery generation; live reader leases can temporarily protect more.
- Cache lifecycle sweeps inactive repository namespaces and removes dead worktree ownership records after the safety window.
- Suppression uses immutable index-generation identity plus hashes for cited evidence instead of snapshotting the entire repository. The Vega failure-path measurement fell from about 30.6 seconds to 0.38 seconds.
- Runtime-boundary direct observations carry per-file coverage. An incremental collection re-extracts affected files, removes deleted-file observations, and reuses exact unchanged-file observations.
- Shared worktree generations already publish, attach, and fork an exact committed-`HEAD` baseline. Integration tests cover simultaneous cold worktrees, dirty private overlays, peer import, and rejection of a dirty peer cache.
- Runtime call recovery now uses one cached compiler-resolved call-site view. Direct argument-to-parameter transfers and finite static values are shared graph facts with proof spans and explicit unknowns.
- Workspace affected closures are partitioned by owning TypeScript project, and the compiler service retains one warm session per project.
- TypeScript fingerprints now contain compiler-selected project inputs instead of every TypeScript-looking repository file. Tracked deletions are recorded as deletions rather than permanent `unreadable` inputs, and nested projects use the most-specific owning `tsconfig` with the root as fallback.
- HTTP, mount, and carrier derivation reuse the shared call/value substrate. Whole-repository carrier closure fell from about 15.2 seconds before the change to 87-140 milliseconds afterward.
- Compiler references whose exact call syntax is missing or ambiguous become named candidate frontiers with a source location and stopped-proof reason; they do not disappear and cannot create exact links.
- Clean-versus-incremental equality fixtures cover terminal/address changes, wrapper calls, mounts, carriers, registry keys, ambiguity removal, and deletion.
- A live four-project update produced 45 documents across two compiler projects, patched one candidate SQLite generation atomically, reused 706 unchanged boundary file facts, and published successfully.
- Full repository verification passes: formatting, ESLint, API compatibility, TypeScript public-consumer compilation, skill-link checks, 271 test files, and 2,170 tests.
- The first completed Luna 5.6 max benchmark was diagnostically useful but not a win. Treatment used 5,502,814 model tokens and 377,182 uncached tokens versus control's 4,409,801 and 252,873. Both answers were strong; treatment was slower and did not establish higher accuracy.
- That treatment materialized a 12,624-identity `search issue` result into roughly 481,000 characters over 15 transport continuations. Search now stops broad human identity manifests at selection time, reports exact total cardinality, returns representative identities and ranked scope recovery commands, and never creates a cursor for the withheld identities. Complete identities remain available to programmatic consumers.
- The treatment-only rerun proved that this selector fix is necessary but insufficient. It avoided the broad selector yet used 7,627,621 model tokens and 332,133 uncached tokens in 59 tool calls, versus the matched control's 4,409,801 and 252,873 in 109 calls. The resolver recognized `db.insert(...)` but not transaction callback aliases such as `tx`, raw SQL skip-locked claims, or the fact that a matched insert/`FOR UPDATE SKIP LOCKED` pair is a work queue rather than an ordinary persistence relationship. The resolver now proves transaction-local persistence receivers and promotes only same-resource insert/skip-locked-claim pairs to a traversable database-backed queue boundary.

## Current path

1. Project inputs are fingerprinted and compared with the accepted generation.
2. The affected-set planner decides whether a TypeScript edit is safe for closure-based incremental indexing.
3. A long-lived TypeScript index service emits affected SCIP documents.
4. Those documents patch a candidate SQLite generation.
5. Validation succeeds before the candidate becomes the accepted generation.
6. Immutable local generations, TypeScript fragments, overlays, and repository-shared generations support publication and reuse.

The architecture supports this path. The observed defects were broader than the initial four: configured TypeScript directories and tracked deletions became unreadable fingerprints; source files excluded by every compiler project still invalidated the index; overlapping root/nested projects looked ambiguous; fragment generations were never pruned; inactive repository namespaces were never swept; and suppression captured a full repository snapshot even though its cited evidence was hashed separately. Those implementation defects are corrected in the current working tree.

## Runtime-boundary derivation correction

A call graph is the set of callable program units and the compiler-resolved invocation links between them. It establishes _which implementation invokes which other implementation_, but it does not by itself retain the values passed along those links.

Value flow is the set of proved transfers from a value's origin through parameters, return values, local bindings, object fields, and call arguments to a use. The current `dataflow` command reports symbol definitions, references, and enclosing producers/consumers; it deliberately does not yet prove value chains such as `x = makePath(); send(x)`. Runtime-boundary derivation therefore cannot call that public query and treat its output as value-level proof.

A runtime boundary is a transfer whose producer and consumer are connected by a runtime addressing mechanism rather than a direct language call—for example an HTTP method and path, a queue address, or a registry key. The direct call graph stops at the producer operation and resumes at the separately registered consumer. Deriving the connection requires both the generic program relationships and the protocol identity carried across the gap.

The implementation should use one internal evidence substrate:

1. Reuse SCIP symbol identity, definitions, references, imports, and resolved call sites as shared graph facts.
2. Add a shared, proof-carrying value-summary layer for literals, constants, parameters, call arguments, return values, and object fields. Each derived fact records its source inputs and span.
3. Keep framework adapters small: they identify terminal operations and assign semantic roles such as HTTP request path, HTTP handler path, queue send address, or registry dispatch key. They do not implement their own graph traversal.
4. Propagate terminal facts over the shared call-site and value-summary edges to a fixed point.
5. Join producer and consumer facts only when their normalized protocol identities are proved equal. Preserve ambiguous or dynamic values as candidates or unresolved frontiers instead of silently omitting them.
6. Cache expensive direct/source/compiler facts with their dependencies. Recompute the compact derived relationship closure from those facts unless measurement proves that closure itself is expensive. Persisting final derived answers is unnecessary state and creates stale-answer risk when the closure costs only milliseconds.

This is a compiler-evidence-backed program graph with a narrow value-flow extension, not a second source index. It can be exact for statically represented relationships. Reflection, runtime-generated addresses, unobserved configuration, and third-party behavior cannot always be proved statically; accuracy means distinguishing proved links from candidates and making every unresolved frontier visible.

A database table is not automatically a runtime control-flow boundary: most reads do not consume a preceding write. A database-backed work queue is the narrower case where one path inserts work and another path claims rows for execution. The initial generic rule requires a same-resource insert and a transaction-scoped `FOR UPDATE SKIP LOCKED` read. Only that proved pair is projected as `queue.send → queue.consume`; ordinary database resource groups remain visible but non-traversable.

The benchmark objective is cumulative model context, not output size in isolation. A concise packet returned early can be charged again on every later reasoning step. The exploration surface must therefore reduce both characters and the number of decision round trips: each abstraction level must answer material behavior, state exact coverage, and name only the unresolved facts worth another drilldown. Locator output that merely causes dozens of later `search`, `outline`, `code`, and native-source calls is not a successful abstraction even when each individual call is bounded.

## Acceptance conditions

The work is complete only when all of the following are true:

1. A one-file production edit in a configured TypeScript project uses incremental document production and patching.
2. A shared-package edit spanning configured projects uses partitioned incremental requests or reports a concrete safety reason for a full rebuild.
3. Runtime-boundary collection reports per-phase duration and the number of files or facts extracted, reused, invalidated, and recomputed.
4. Incremental and clean boundary graphs are structurally equal after each tested terminal, wrapper, mount, carrier, registry, deletion, and rename edit.
5. Every derived fact identifies the direct observations, call/value edges, and source files that justify it; the relationship closure is recomputed from the current generation's retained evidence rather than trusting a cached final answer.
6. Exact links are never produced from ambiguous or unsupported flow. Those cases remain candidates or named unresolved frontiers.
7. Repeated edits retain two ordinary local generations, prune obsolete fragment/overlay generations, and do not create permanent per-run checkout caches.
8. Suppression stays on the generation-scoped fast path while continuing to hash cited evidence.
9. Full repository verification passes before any benchmark conclusion or merge into `main`.
10. Across several arbitrary exploration tasks, the scip-query treatment matches or exceeds control accuracy while materially reducing exploration tokens; source fallback usage is reported rather than hidden.

## Open uncertainty

Repository-shared cache identity currently follows the Git common-directory path. Git worktrees therefore share one repository namespace, while independent clones of the same commit do not. The safe first benchmark design is to create disposable worktrees from one retained canonical clone. Changing repository identity to follow remote content is a separate compatibility decision because unrelated repositories can share remotes or histories without sharing local trust or configuration.
